# C5 Triage, Classification & Incident Management

## Control Objective

This chapter addresses assessing, classifying, declaring, recording, and coordinating incidents consistently, so that response effort matches impact and the record supports later decisions, reviews, and legal obligations.

---

## C5.1 Classification & Prioritization

Incidents must be rated on consistent criteria so that the most damaging ones receive attention first.

| # | Description | Level |
| :--------: | ------------------------------------------------------------------------------------------------------------------- | :---: |
| **5.1.1** | **Verify that** each incident is assigned a severity level using documented criteria. | 1 |
| **5.1.2** | **Verify that** severity criteria consider functional impact, information impact, recoverability, and legal or safety consequences. | 2 |
| **5.1.3** | **Verify that** each severity level defines response time targets, required roles, and escalation and communication requirements. | 2 |
| **5.1.4** | **Verify that** incidents are categorized by type using a defined taxonomy. | 2 |
| **5.1.5** | **Verify that** severity is re-evaluated as new information emerges, with each change and its rationale recorded. | 2 |
| **5.1.6** | **Verify that** documented criteria guide prioritization of responder effort when multiple incidents are active at the same time. | 3 |

---

## C5.2 Declaration & Escalation

The decision that an incident is underway must be explicit, timely, and recorded, because it mobilizes the response and may start legal clocks.

| # | Description | Level |
| :--------: | ------------------------------------------------------------------------------------------------------------------- | :---: |
| **5.2.1** | **Verify that** documented criteria define when an incident is declared and which roles are authorized to declare it. | 1 |
| **5.2.2** | **Verify that** the times at which the organization detected, became aware of, and declared each incident are recorded. | 2 |
| **5.2.3** | **Verify that** escalation paths define who is notified at each severity level and within what time. | 2 |
| **5.2.4** | **Verify that** the rationale is recorded when a suspected incident is determined not to be an incident. | 2 |
| **5.2.5** | **Verify that** the criteria and approver for closing an incident are documented. | 2 |

---

## C5.3 Incident Record & Coordination

A single, contemporaneous, protected record of each incident must be kept, since it is the basis for coordination, reporting, and review.

| # | Description | Level |
| :--------: | ------------------------------------------------------------------------------------------------------------------- | :---: |
| **5.3.1** | **Verify that** every declared incident has a record that captures a summary, affected assets, key events, actions taken, decisions, and current status. | 1 |
| **5.3.2** | **Verify that** responder actions are recorded contemporaneously with a timestamp and the identity of the person acting. | 2 |
| **5.3.3** | **Verify that** a dedicated recorder is assigned for significant incidents to document decisions and actions. | 2 |
| **5.3.4** | **Verify that** tasks assigned during an incident are tracked with an owner and completion status. | 2 |
| **5.3.5** | **Verify that** access to incident records is restricted to those with a need to know and is logged. | 2 |
| **5.3.6** | **Verify that** incident records are protected against undetected modification. | 3 |
